# EcoCycle

EcoCycle is an Android-first Flutter application for the ITS Web & Mobile App Developer final project. It helps citizens discover recycling facilities, explore available material information and experiment with a demonstrative waste-monitoring experience. It is not connected to a municipality, a waste management operator, sensors or a proprietary backend.

## Features

- Firebase email/password registration, sign-in, password recovery and session persistence.
- A first-access onboarding flow with local material preferences and an ecological goal.
- Interactive OpenStreetMap map with search, filters, an API-backed list, point preview and detail.
- Optional Android location, recentering and distance-based list ordering. No background tracking.
- Demonstrative container states and stable synthetic sensor readings.
- Local reward redemption with a demonstrative balance and history.
- Local reports with category, description, optional coordinates, a linked OSM point and an optional photo.
- Firebase profile name editing, password recovery, logout and persistent light/dark theme.
- Google and Apple authentication code behind configuration flags; Facebook is not implemented until the required external setup is available.

## Technologies and structure

Flutter, Dart, Material 3, Firebase Core/Auth, HTTP, flutter_map, latlong2, geolocator, SharedPreferencesAsync, image_picker, path_provider, google_sign_in and url_launcher. The last five packages support persistence, photos, private file storage, Google identity and the OSM attribution link respectively. No Provider or Riverpod is required.

## Setup and running

Use the Flutter version compatible with the Dart SDK constraint in `pubspec.yaml`, an Android SDK and a device or emulator with internet access. Keep the existing application ID `com.example.ecocycle`, FlutterFire configuration and `android/app/google-services.json`. Enable Email/Password in Firebase Authentication. Never commit service account keys, OAuth secrets or user passwords.

```powershell
flutter pub get
flutter run
```

If Firebase configuration must be recreated, use the existing EcoCycle Firebase project and `flutterfire configure` for Android. Do not create a second Firebase project. Android permissions are already declared in the existing manifest: INTERNET, ACCESS_COARSE_LOCATION and ACCESS_FINE_LOCATION. Location is requested only when a user presses a location control.

## REST API and map

- Base URL: `https://ovp.dresel.systems`
- Endpoint: `GET /api/interpreter`
- Query parameter: `data` (Overpass QL; URL encoded by `Uri.https`). No API key.

```overpass
[out:json][timeout:15];
nwr["amenity"="recycling"](45.00,7.58,45.14,7.77);
out center;
```

The response is JSON with an `elements` array. Node coordinates use `lat` and `lon`; ways and relations use `center.lat` and `center.lon`. The model keeps the OSM element type and ID, coordinates and tags. `recycling_type=container` denotes a container, while `recycling_type=centre` denotes a collection centre; neither is a material. Materials are derived only from `recycling:*` tags explicitly marked `yes`. Missing names, addresses and material metadata are not fabricated.

The map, list, preview and detail use these same real records. The query is intentionally bounded to Turin and does not run on every pan or zoom. The user can explicitly refresh. A 25-second HTTP timeout, HTTP status checks, malformed response handling, and loading/empty/error/retry states are included. No sample data replaces a failed REST request.

`flutter_map` renders the map; the OSM raster tile server provides the basemap; Overpass is a separate data source. Tile URL: `https://tile.openstreetmap.org/{z}/{x}/{y}.png`. Attribution is visible and links to https://www.openstreetmap.org/copyright (OpenStreetMap contributors, ODbL). A descriptive User-Agent is sent on Android. Do not use this demonstration app for bulk downloads or offline tile harvesting. Review the public [tile policy](https://operations.osmfoundation.org/policies/tiles/) and applicable Overpass instance limits before distribution. The standard light OSM raster tiles remain the same in dark mode; app chrome, controls and content use the dark theme. Public endpoints have no guaranteed service availability.

## Real data versus simulated data

| Real | Simulated / local only |
| --- | --- |
| Firebase identity, name, email and authentication | Reward catalog, initial XP, level and redemptions |
| OSM element identifiers, coordinates and available tags | Container fill, temperature, capacity, weight, gas readings and operational status |
| OpenStreetMap cartography | Demonstrative alerts; no live monitoring |
| Authorized device location | Onboarding preferences and theme |
| Photo selected by the user | Reports are stored locally; never sent to a public authority |

A deterministic seed based on `osmType/id` makes the same simulated container readings stable across rebuilds and app restarts. Centres and points with unknown type do not display fictional container readings. The green/orange/red fill thresholds are <50%, 50–79%, >=80%; maintenance and unavailable states override them. All telemetry is illustrative.

## Local storage

`SharedPreferencesAsync` stores small local records. Onboarding, rewards and reports use Firebase UID-prefixed keys, while the device theme is global. Photos are copied into an app-private documents directory (separated by UID) before recording a report. Uninstalling or clearing app data removes local records. Local records are not a cloud backup or encrypted account vault. Android may interrupt an image pick if the activity is killed; the app asks the user to select again rather than attaching a photo from an uncertain session. No passwords or access tokens are stored manually.

## Social authentication

Google and Apple buttons are hidden unless their build flags are explicitly enabled after external configuration. Do not enable the flags before verifying the corresponding provider.

For Google on Android:

1. Run `cd android; .\gradlew signingReport; cd ..` in PowerShell. Copy the SHA-1 and SHA-256 for the signing variant that will be used.
2. In the existing Firebase project, Settings > General > Your apps > Android (`com.example.ecocycle`), add the fingerprints.
3. Authentication > Sign-in method > Google: enable the provider and set the required support email.
4. Download the updated `google-services.json` into `android/app/`, replacing the existing file only after checking the project and package match. Ensure the configuration includes a web OAuth client for Google Sign-In. Complete the OAuth consent configuration if Google requests it.
5. Run `flutter run --dart-define=ECOCYCLE_GOOGLE_SIGN_IN=true`. Test sign-in, cancellation, wrong configuration and logout on a Google Play services-capable Android device.

Apple uses Firebase's native federated flow only when enabled with `--dart-define=ECOCYCLE_APPLE_SIGN_IN=true`. An Apple Developer account and a configured Services ID, team ID, key and Firebase return URL may be required. Configure them only if you already have the necessary access; no paid service has been activated. This path is not verified.

Facebook is intentionally not shown. To implement it, create/configure a Meta developer app with Facebook Login, enable Facebook in Firebase using the real App ID and secret, configure the Firebase OAuth redirect URL and Android key hashes/package, then integrate `flutter_facebook_auth` following its native setup and test the provider. No fake credentials, placeholder success or unused SDK is included.

See [Firebase federated authentication](https://firebase.google.com/docs/auth/flutter/federated-auth), [Google Sign-In](https://pub.dev/packages/google_sign_in) and `docs/integrations.md`.
